Tracking de Produtos GO

Painel de visibilidade do ciclo de vida do SKU — do cadastro inicial até a disponibilidade no site/loja física. Domínio exclusivo de produtos 1P (First Party). Fonte de verdade: este repositório.

💡Problema

O time de Gestão de Operações não tem visibilidade centralizada do ciclo de vida de um SKU. As informações estão espalhadas em GO/Catálogo, LN (Infor), Tax Web, Inventário, Admin e Oferta. O único jeito de rastrear um produto é consultar cada sistema manualmente — gerando lead time alto, falta de clareza sobre fonte de verdade e retrabalho.

OBJETIVO

Uma visão unificada do status de um SKU em todas as etapas do pipeline — somente leitura / observabilidade.

🎯Escopo

No Escopo

  • Produtos 1P (First Party)
  • SKUs com estoque ativo
  • Painel de status por etapa
  • Filtros por categoria / flags
  • Exportação da lista

Fora do Escopo

  • Produtos 3P (marketplace)
  • Alteração de dados
  • Gestão de cadastro
  • Integração com Pricing (só leitura)
  • Validação SQL↔MongoDB (V2)

📖Conceitos-Chave

SKU OFF
SKU do backoffice — visão operacional interna. É o que o painel GO exibe. Audiência: Analistas, TI, Compras.
SKU ON
SKU que aparece no site para o cliente final — vitrine. Para 1P pode ter preço e disponibilidade diferentes do OFF.
1P
Produto vendido/entregue pela própria Casas Bahia. SKU ON ≠ SKU OFF. Escopo do tracking.
3P
Produto de marketplace (vendedor parceiro). SKU ON = SKU OFF. Fora do escopo.
MONGOS
MongoDB interno que serve os dados para o site. Réplica das flags do SQL. Falha de replicação = SKU invisível no site.
Rundeck
Sistema de automação de jobs que propaga as flags de SKU e Produto após ativação no backoffice (SKLogista → SKU → Produto, ~1 min).

🚦Regras de Exibição — Múltiplas Flags Simultâneas

Se qualquer flag abaixo estiver inativa, o SKU não aparece — mesmo que as demais estejam corretas.

⚠️ Simplificação: O fluxo de propagação começa pelas 3 flags abaixo (caminho crítico). Mas a exibição real requer também Marca e 4 níveis de Categoria — ver detalhe completo em docs/conceitos/regras-exibicao-sku.md
💰
SKLogista · SKLogista Preço
FlagAtiva = 1 em ambas — Regula precificação (site, app, loja)
↓ Job Rundeck propaga (~imediato)
📦
SKU
FlagAtiva = 1 · FlagAtivaERP = 1 · FlagSkuProduzido = 1 · FlagSkuSaldoDisponivel = 1
↓ replica para Produto (~1 minuto)
🛍️
Produto
FlagAtiva = 1 · FlagExibe = 1 (atualizado automaticamente via pulso de estoque)
↓ replicado para MongoDB (MONGOS) → site
🏷️
Marca + Categoria (4 níveis)
Marca.FlagAtiva = 1 · Categoria.FlagAtiva = 1 (e CategoriaPai, CategoriaNeto, Departamento)
Cenário de falha: Todas as flags podem estar corretas no SQL mas o SKU não aparece no site se a replicação MONGOS falhar.
